# Список покупок по блюду

Небольшое приложение: пользователь пишет блюдо, выбирает число людей и формат ответа. Обработчик вызывает GigaChat и возвращает список продуктов. Если выбран формат «Список + шаги», к списку добавляются короткие шаги приготовления.

Цепочка одна: поле ввода → `generate_shopping_list` в `llm.py` → поле результата. Проверка текста стоит до создания клиента и до сетевого запроса. Секреты читаются только из переменных окружения.

## Состав

- `streamlit_app.py` — интерфейс Streamlit
- `llm.py` — проверка ввода, запрос к модели, разбор ошибок
- `tests/test_scenarios.py` — проверка трёх типов ввода и карты ошибок
- `.env.example` — перечень переменных без секретов

Порог длины запроса — 500 символов.

## Требования

- Python 3.10 или новее
- ключ доступа GigaChat

## Запуск

```bash
cd shopping-list
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
```

Откройте `.env` и вставьте ключ авторизации из личного кабинета GigaChat:

```bash
GIGACHAT_CREDENTIALS=ваш_ключ
```

Ключ в репозиторий не кладите. Файл `.env` уже указан в `.gitignore`.

Запуск интерфейса:

```bash
streamlit run streamlit_app.py
```

Откроется страница с полем «Что приготовить», списками «На сколько человек» и «Формат», кнопкой «Сгенерировать список покупок» и полем «Список покупок».

Если TLS-сертификат Минцифры ещё не установлен и клиент не может проверить сертификат сервера, для локальной проверки можно временно поставить `GIGACHAT_VERIFY_SSL_CERTS=false`. Для обычной работы лучше скачать Russian Trusted Root CA и указать путь в `GIGACHAT_CA_BUNDLE_FILE`.

Автоматические проверки:

```bash
pytest
```

Они не ходят в сеть: модель подменяется, а для ошибок подставляется исключение с кодом статуса.

## Что уходит в модель

В запрос явно попадают блюдо, число людей и выбранный формат.

- «Список продуктов» — только продукты, каждый с новой строки: `- продукт — количество`.
- «Список + шаги» — тот же список и затем 5–8 коротких шагов.

Число людей меняет объём продуктов в инструкции модели.

## Три проверки сценария

1. Нормальный текст. Введите `паста карбонара`, оставьте 2 человека и формат «Список продуктов», нажмите кнопку. В поле «Список покупок» появляется список, по продукту на строку. Запрос к API уходит.
2. Пустой текст. Очистите поле блюда и нажмите кнопку. Появляется фраза «Напишите, что хотите приготовить.» Запроса к API нет.
3. Слишком длинный текст. Вставьте больше 500 символов и нажмите кнопку. Появляется фраза «Слишком длинный текст — сократите или разбейте на части.» Запроса к API нет.

Те же три случая закрыты тестами `test_normal_text_returns_shopping_list`, `test_empty_text_does_not_call_api` и `test_long_text_does_not_call_api`.

## Как воспроизвести ошибку доступа

Уберите ключ и запустите приложение заново:

```bash
unset GIGACHAT_CREDENTIALS
unset GIGACHAT_ACCESS_TOKEN
```

В `.env` оставьте `GIGACHAT_CREDENTIALS` пустым. Введите `омлет` и нажмите кнопку. Интерфейс показывает одну фразу: «Не настроен доступ к сервису.» Трассировки нет, и текст ключа на экран не попадает. Повторного запроса нет.

Другие сбои тоже приходят одной фразой:

| Ситуация | Фраза | Повтор |
| --- | --- | --- |
| 4xx, нет ключа или ключ не принят | Не настроен доступ к сервису. | нет |
| 5xx | Сервис временно недоступен. Попробуйте позже. | один |
| таймаут или сеть | Не удалось получить ответ. Попробуйте ещё раз. | один |
| пустой или неразобранный ответ | Пустой ответ модели. Попробуйте переформулировать вопрос. | нет |
